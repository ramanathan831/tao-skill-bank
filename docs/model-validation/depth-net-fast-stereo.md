Issues found:
- Model skill issues:
  - The instructions said the bp2 commercial checkpoint ships with the skill,
    but the default PyT image and S3 dataset location did not contain
    `model_best_bp2_serialize.pth`.
  - The local checkpoint guidance used `dn_model_latest.pth` as the chained
    action example instead of the exact epoch/step checkpoint.
  - Deploy metadata listed `gen_trt_engine.trt_engine` as both an input and an
    output even though it is generated by the action.
- Config issues:
  - DepthNet deploy passes `gen_trt_engine.tensorrt.workspace_size` through as
    GiB in the validated image. The template value `4096` inflated the logged
    builder pool request; use `4` for a 4 GiB builder pool.
  - TensorRT engine build time is significant for FFS. A 224x224 FP32 engine
    completed in 242 seconds; the initial 320x320 FP16 smoke build was stopped
    after an extended compile window.
- Dataset issues:
  - Direct Docker specs must preserve the `/data/...` annotation paths by
    mounting the extracted data at `/data`.
- Checkpoint issues:
  - Checkpoints are nested under the task folder:
    `<results_dir>/train/model_epoch_<epoch>_step_<step>.pth`.
- Docker/local execution issues:
  - The deploy image emits non-fatal telemetry warnings after successful deploy
    actions.
  - Deploy `evaluate` failed after successful prediction generation with
    `TypeError: only 0-dimensional arrays can be converted to Python scalars`
    in the deploy stereo evaluator.
- Fresh-install issues:
  - No bp2 checkpoint was available in the default PyT image or the inspected S3
    data/checkpoint locations; users must provide it for bp2 raw-deploy or
    bp2-finetune accuracy validation.

Fixes made:
- Removed `gen_trt_engine.trt_engine` from deploy action inputs while keeping it
  as a generated output mapped by `create_engine_file`.
- Documented that the bp2 checkpoint path is a required artifact, not guaranteed
  to exist in the default image.
- Added exact checkpoint resolver guidance for nested
  `model_epoch_<epoch>_step_<step>.pth` checkpoints and `dn_model_latest.pth`.
- Updated the deploy workspace template and docs to use `workspace_size: 4` for
  the current DepthNet deploy builder behavior.
- Documented the current deploy `evaluate` metric-reduction failure and the
  PyT-evaluate/TRT-inference workaround.

Remaining issues:

- The validation trained from scratch because no bp2 checkpoint was available;

- AutoML is declared but not runnable from this model skill because the train
